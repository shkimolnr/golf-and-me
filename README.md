# Golf & Me (골프와 나)

> 매홀 기록은 간단하게, 라운드 후 분석은 깊게.

Golf & Me는 실력 향상에 관심 있는 아마추어 골퍼를 위한 모바일 웹(PWA) 서비스입니다. 스마트폰만으로 라운드를 기록하고, 플레이 패턴을 분석해 다음 연습 방향을 찾도록 돕는 것을 목표로 합니다.

## 현재 단계

- 제품 단계: Phase 1 Alpha 구현·검토
- 기준 PRD: v2.1
- 우선 목표: 라운드 생성 → 홀별 기록 → 라운드 요약의 핵심 흐름 검증
- 원본 참고 문서: `sources/golf_prd_v2.md` (읽기 전용)

## MVP 범위

1. Google 로그인과 최초 온보딩(기본 티·거리 단위·클럽 구성 확인)
2. 새 라운드 생성
3. 전반/후반 스코어카드
4. 홀별 스코어·벌타·FIR·GIR·퍼팅 기록
5. 자동 스코어 계산과 라운드 요약
6. 홈 누적 통계
7. 클럽별 거리 관리
8. 로컬 우선 저장·계정 동기화와 입력 복구
9. 계정 탈퇴와 전체 기록 영구 삭제

공개 MVP는 기능 구현만으로 개시하지 않습니다. 실제 테스트 계정의 전체 삭제·재가입 검증, 비식별 삭제 처리 기록, Google 연결 해제 방침, 백업 소멸 원칙, 공개 약관·개인정보처리방침과 OAuth 브랜드 점검을 `TASK-032` 출시 차단 조건으로 관리합니다.

프로덕션에서는 한 번 불러온 앱 화면을 기기에 저장해 일시적인 오프라인 재진입·새로고침에도 기록을 계속할 수 있고, 연결이 돌아오면 계정 저장을 자동 재시도합니다.

Alpha 기록 화면은 퍼팅 시작 위치를 `그린/엣지`로 구분해 마지막 샷 결과와 공식 퍼팅 수를 계산하며, 작성 중·완료 라운드 모두 확인 절차를 거쳐 삭제할 수 있습니다.
골프장·전후반 코스 선택 오류는 세 번째 플레이 홀까지 기존 기록 유지 또는 초기화를 선택해 바로잡을 수 있고, 네 번째 홀 이후와 완료 라운드에서는 기록 구조 보호를 위해 해당 항목을 잠급니다.
로그인 사용자의 저장 완료 라운드는 로컬에 먼저 보존한 뒤 Supabase와 동기화하며, 다른 기기에서는 같은 계정의 최신 기록을 병합해 불러옵니다.
홈의 `나의 라운드 리포트`는 완료 기록만 대상으로 평균 스코어·총 라운드·GIR·평균 퍼팅·FIR·베스트 스코어를 누적 집계하며, 결측값은 단일 라운드 결과와 같은 기준으로 분모에서 제외합니다.
`내 골프백`은 현재 클럽 구성과 날짜별 전체 비거리 세트를 관리합니다. 일부 클럽만 다시 측정해도 같은 거리 기준의 나머지 값은 직전 세트에서 이어받고, M/YD가 바뀌면 정규화 값으로 환산합니다. 로그인 사용자의 구성과 모든 거리 세트는 Supabase에 보존해 다른 기기에서도 복원합니다.

홀 기록은 퍼팅 입력 여부와 관계없이 사용자가 `임시 저장`과 `홀 기록 완료`를 명시적으로 구분합니다. 라운드에 저장된 클럽은 당시 ID와 표시명을 스냅샷으로 보존해 이후 골프백에서 제거해도 과거 기록과 통계가 바뀌지 않게 합니다.

2026-08-31 기준 실제 Supabase에도 샷의 클럽 ID·표시명 스냅샷 및 프로필 기본 거리 단위 마이그레이션을 적용했습니다. 운영 DB에 없던 `round_holes.swing_count`도 보강하고 라운드 자동 재저장 성공과 지연 안내 해제를 확인했습니다.

제품 분석은 GTM 없이 GA4 웹 데이터 스트림을 앱 코드에서 직접 사용합니다. 기본값은 분석 미선택이며, 온보딩 전 선택 화면 또는 계정 메뉴에서 허용한 경우에만 스크립트를 로드하고 이용 흐름 이벤트를 보냅니다. 이메일·계정 ID·토큰·전체 URL·골프 기록·자유 입력·원본 오류는 GA4에 보내지 않습니다. 2026-09-01 Preview 전용 속성·환경변수에서 동의·철회, 로그인과 18홀 퍼널, 중복 방지, 비식별 URL, 광고 개인화 차단을 실제 DebugView로 검증했습니다. Production GA4는 개인정보처리방침과 운영 설정을 확정할 때까지 비활성 상태입니다.
운영상 최소 오류 진단은 GA4와 별도로 Supabase `app_diagnostics`에 저장합니다. 인증된 요청만 허용하고, 임시 incident ID·실패 단계·정규화 분류·안전한 HTTP 상태·앱 버전·일반화된 플랫폼·온라인 여부·발생/복구 시간·횟수만 보냅니다. 사용자 식별자·원본 오류·골프 기록은 제외하며, 네트워크 상황에서는 안전한 항목만 기기에 최대 20건 임시 보관합니다. 2026-08-31 Production DB에 마이그레이션·RLS·server-role 전용 함수를 적용하고 Vercel Production Secret 등록 및 앱 배포를 마쳤습니다. 같은 비식별 test incident의 실패 2회가 한 행의 횟수 2회로 합쳐지고 복구가 연결되는 DB 함수 검증 후 테스트 행도 삭제했습니다. 인증된 브라우저 전송 종단간 검증과 보관 삭제 스케줄러는 아직 남아 있습니다.
로그인 체감 속도는 로그인 시작부터 세션 복원·기록 준비까지의 최근 20개 구간 시간을 기기에만 보관합니다. 2026-08-31 모바일 영상 점검에서 앱 복귀 후 화면 준비 속도는 현재 단계에서 통과 처리했으며, GA4 직접 연동이 활성화된 뒤 동의한 사용자 이벤트의 단계별 `duration_ms` 추세로 다시 확인합니다.
2026-08-31 PKCE 재로그인 검증 중 원격 프로필·라운드·클럽 기록 조회가 한 번 실패한 사례를 관찰했습니다. 원인은 데이터 양으로 확정하지 않았으며 네트워크·인증 세션·Supabase 응답을 단계별로 분리합니다. 자동 재시도는 최대 1회로 제한하고 한 영역의 실패가 전체 준비를 막지 않게 했습니다. 완료 라운드는 홈에 요약만 먼저 불러오고 상세 원본은 열 때 가져오며, 비거리도 최신 세트부터 불러옵니다. 저장은 전체 기록이 아니라 변경된 라운드만 전송하고, 기존 원본과 전체 거리 이력은 삭제하지 않습니다. 이 구조의 Supabase migration과 250개 라운드·60개 거리 세트 회귀시험을 완료했으며 배포 E2E는 `TASK-046`으로 관리합니다.
오류 관측은 현재 `oauth`, 프로필·라운드·클럽 조회·저장, 라운드 삭제와 계정 삭제를 비식별로 연결합니다. 같은 incident는 최신 시각과 횟수만 갱신하고 정상 복구를 연결합니다. 거리 이력·로컬 파싱·재시도 등 추가 단계, 분산 추적·알림·대시보드는 실제 장애 패턴을 확인한 뒤 확장합니다.
Beta 테스트 계정 신청은 로그인 화면에서 Google 이메일만 받아 Vercel 서버를 거쳐 비공개 Slack 채널로 전달합니다. 별도 개인 요청함이나 자동 이메일은 만들지 않고, Webhook 비밀값은 Vercel 서버 환경변수에만 보관합니다.
로그인 사용자는 홈 상단과 계정 메뉴의 `새소식`에서 홀 정보 추가·기능 개선·오류 수정 내용을 날짜순으로 확인합니다. 공지는 `src/data/news.js` 한 곳에서 관리하며 개인화·읽음 동기화·푸시는 사용하지 않습니다.

검증된 일부 골프장의 홀·티별 거리 템플릿은 Phase 1에 앞당겨 포함했습니다. AI 코치, GPS 자동 매칭, 전국 단위 데이터 확장과 하드웨어 연동은 MVP 이후 단계에서 다룹니다.
날씨·감정 체크·이메일 정기 리포트는 현재 Alpha 결과 계산에 쓰이지 않으므로 입력 부담과 외부 운영 의존성을 늘리지 않고 Phase 2에서 분석·동의 정책과 함께 도입합니다.

## 골프장 홀 정보

- 운영 원본: 단일 시트 누적형 `골프와나_골프장마스터.xlsx`
- 앱 데이터: 원본을 정규화한 `src/data/golfCourseDatabase.json` 정적 스냅샷
- 연결된 골프장: 검색 결과의 `[홀 정보]` 후보를 선택하면 시작 전 코스·티·단위를 한 번 확인한 뒤 PAR와 홀 거리를 자동 입력
- 연결되지 않은 골프장: 전반 1–9번·후반 10–18번을 생성하고, 자유 입력한 PAR와 홀 거리로 정상 기록
- 코스 자체가 공식 1–18번을 가진 골프장은 원본을 보존한 채 앱에서 `코스명 OUT / 코스명 IN` 구간을 파생해 선택

## 기술 기준

- Frontend: React + Vite + CSS
- Backend / Database: Supabase (PostgreSQL)
- Authentication: Google OAuth 2.0
- Hosting: Vercel
- Production URL: https://golf-and-me.vercel.app

## 로컬 화면 미리보기

개발 서버에서 `?preview=1`을 붙이면 Google 로그인 없이 개발 전용 사용자로 진입합니다.

```text
http://127.0.0.1:5190/?preview=1
```

미리보기 데이터는 해당 브라우저와 접속 주소의 로컬 저장소에만 보관되며 프로덕션 빌드에서는 이 우회가 활성화되지 않습니다.

### 모바일 Google 로그인 확인

- 실제 로그인 시험에는 `?preview=1`을 붙이지 않습니다.
- 같은 네트워크의 휴대폰에서 개발 PC의 주소(예: `http://192.168.x.x:5190/`)로 접속합니다.
- Supabase Auth의 Redirect URL 허용 목록에 해당 개발 주소의 `/**` 패턴을 추가합니다.
- Google OAuth에는 Supabase가 제공하는 HTTPS callback URL을 등록합니다.
- 로컬 IP는 바뀔 수 있으므로 지속적인 테스트에는 HTTPS 배포 주소를 사용합니다.
